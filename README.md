# ⚡ 薛朗的联机工具（MCLink）—— 我的世界 Java 版 P2P 联机

让不在同一个局域网的朋友直连你的 Minecraft 世界：**电脑（Windows/Linux/macOS）和手机 FCL 等启动器（Android）通用**，手机还能直接用浏览器打开 Web 控制台操作。

纯 Python 标准库实现，**零依赖、无需安装任何第三方包**。

## 联机方式总览

| 方式 | 需要条件 | 本工具的角色 |
|---|---|---|
| 局域网直连 | 同一 Wi-Fi/网线 | 查看本机 IP、自动检测游戏端口，MC 里直接填 IP |
| IPv6 直连 | 双方都有公网 IPv6 | 显示你的 IPv6 地址，MC 里填 `[IPv6]:端口` |
| **P2P 打洞（主打）** | 一个信令服务器（见下文） | 自动打洞 + 中继兜底，MC 里填 `127.0.0.1:25565` |
| Tailscale / ZeroTier 等 | 各自注册账号、组建虚拟局域网 | 见「第三方方案」，本工具不内置 |

> 注意：Java 版只能和 Java 版联机（电脑版、FCL 等手机 Java 启动器都是 Java 版，可以互连）；基岩版不适用。

## 快速开始

### 房主（开世界的一方）

1. 打开 `mclink_desktop.py`（双击运行 `启动MCLink.bat` 也行）
2. 在 MC 单人世界里点「对局域网开放」，记下聊天栏显示的端口（如 `54321`）
3. 工具里：模式选 **房主**，填信令服务器和房间号，游戏端口填上一步的端口
4. 点「开始联机」，把房间号告诉朋友

### 玩家（加入的一方）

1. 打开 `mclink_desktop.py`，模式选 **玩家**，填同一个信令服务器和房间号
2. 点「开始联机」，等状态变成「已连接」
3. MC → 多人游戏 → 直接连接 → 填 `127.0.0.1:25565`

### 手机玩家（FCL 等 Java 启动器）

两种用法任选：
- **方案 A（推荐）**：手机装 [Termux](https://termux.dev) 或 Pydroid 3，把整个 mclink 文件夹传到手机，`python mclink_core.py join 房间号 --server 服务器:端口`，然后 FCL 里填 `127.0.0.1:25565`
- **方案 B**：电脑端点「启动手机控制台(Web)」，手机浏览器打开显示的地址，在网页上操作电脑端

### 纯命令行用法

```bash
python mclink_core.py info                 # 查看本机 IP / IPv6 / 游戏端口
python mclink_core.py web 8765             # 启动 Web 控制台（手机浏览器可操作）
python mclink_core.py create 房间号 --server 1.2.3.4:42339 --port 54321   # 房主
python mclink_core.py join   房间号 --server 1.2.3.4:42339               # 玩家
```

## 信令服务器（P2P 联机必需，需要你部署）

P2P 打洞需要一台**有公网 UDP 端口**的服务器帮双方交换地址；打洞失败时它还负责中继流量兜底。

- 支持环境：任意云服务器/VPS（阿里云、腾讯云轻量、Oracle 永久免费档等都行）
- 不支持：普通网页托管 / 函数计算（不支持 UDP）
- 运行：`python mclink_server.py --port 42339`，防火墙/安全组放行该 **UDP** 端口
- 纯标准库，服务器上无需装任何依赖

**没有服务器？** 客户端里把信令服务器填成局域网内任一台机器也能在「跨网段但可达」的场景测试；正式跨网联机需要一台公网机器。第三方方案（Tailscale 等）不需要自建服务器，见下文。

## 第三方联机方案（需自行注册，本工具未内置）

| 方案 | 特点 | 门槛 |
|---|---|---|
| [Tailscale](https://tailscale.com) | 组虚拟局域网，稳定好用 | 双方注册账号装客户端 |
| [ZeroTier](https://zerotier.com) | 同上，老牌 | 双方注册账号 |
| [playit.gg](https://playit.gg) | 免费隧道，房主单人装即可 | 房主注册账号 |
| 樱花内网穿透 / frp | 免费隧道节点 | 需注册/自建 frp 服务端 |

这些都是成熟方案，注册登录后按官网指引即可，和本工具不冲突。

## 工作原理

```
玩家 MC 客户端 ──► 127.0.0.1:25565（本地监听）
                        │  隧道（UDP 打洞直连，失败则服务器中继）
                        ▼
              房主端 ──► 127.0.0.1:游戏端口（MC 局域网世界）
信令服务器：只负责交换公网地址 + 中继兜底，不参与游戏数据（打洞成功时）
```

- 隧道帧格式：`魔数"MC" + 类型(1B) + 流ID(2B) + 载荷`，类型：打洞/开流/数据/关流
- 信令报文：JSON over UDP，房主和玩家通过房间号配对
- 打洞超时 8 秒自动切换中继；中继下全部流量经服务器转发

## 已知限制

- 对称型 NAT（手机流量常见）打洞必失败 → 自动走服务器中继，延迟取决于服务器位置
- 中继模式下服务器需承担双方流量，带宽小的 VPS 会有延迟
- 房主必须先「对局域网开放」才能被接入；端口每次开放都可能变
- 防火墙首次运行会弹窗，选择「允许访问」即可

## 自测

```bash
python test_mclink.py
```

在本机完整跑一遍：信令服务器 + 房主端 + 玩家端 + 模拟游戏端口，验证 TCP/UDP 双向转发和并发连接。
