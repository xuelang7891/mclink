# ⚡ 薛朗的联机工具（MCLink）—— 我的世界 Java 版 P2P 联机

让不在同一个局域网的朋友直连你的 Minecraft 世界：**电脑（Windows/Linux/macOS）和手机 FCL 等启动器（Android）通用**，手机还能直接用浏览器打开 Web 控制台操作。

纯 Python 标准库实现，**零依赖、无需安装任何第三方包**。

## 联机方式总览

| 方式 | 需要条件 | 本工具的角色 |
|---|---|---|
| 局域网直连 | 同一 Wi-Fi/网线 | 查看本机 IP、自动检测游戏端口，MC 里直接填 IP |
| **P2P 打洞（主打，IPv4）** | 默认「公共信令」，**无需任何服务器** | 自动探测公网地址 → 打洞 → 失败自动中继兜底 |
| 自建信令打洞 | 一台公网 UDP 服务器（可选） | 同上，信令走你自己的服务器 |
| 手动 IP 打洞 | 双方通过微信等互发公网地址 | 无信令也能打洞（NAT 友好时） |
| Tailscale / ZeroTier 等 | 各自注册账号 | 见「第三方方案」，本工具不内置 |

> 注意：Java 版只能和 Java 版联机（电脑版、FCL 等手机 Java 启动器都是 Java 版，可以互连）；基岩版不适用。

## 快速开始（免服务器，推荐）

1. **房主**：MC 单人世界 →「对局域网开放」→ 记下端口（如 `54321`）
2. **房主**：工具里模式选「房主」、信令方式保持 **公共信令**、填个房间号、游戏端口填上一步的端口 → 点「开始联机」
3. **玩家**：工具里模式选「玩家」、信令方式保持 **公共信令**、填**同一个房间号** → 点「开始联机」
4. 等状态变成「已连接」：玩家在 MC → 多人游戏 → 直接连接 → 填 `127.0.0.1:25565`

打洞成功 = 直连（延迟最低）；失败会自动切「中继模式」兜底（经公共节点转发，能用但速度尽力而为）。

### 手机玩家（FCL 等 Java 启动器）

两种用法任选：
- **方案 A（推荐）**：手机装 [Termux](https://termux.dev) 或 Pydroid 3，把整个 mclink 文件夹传到手机，`python mclink_core.py join 房间号`，然后 FCL 里填 `127.0.0.1:25565`
- **方案 B**：电脑端点「启动手机控制台(Web)」，手机浏览器打开显示的地址，在网页上操作电脑端

### 纯命令行用法

```bash
python mclink_core.py info                 # 查看局域网 IP / 公网 IPv4 / IPv6 / 游戏端口
python mclink_core.py web 8765             # 启动 Web 控制台（手机浏览器可操作）
python mclink_core.py create 房间号 --port 54321          # 房主（默认公共信令）
python mclink_core.py join   房间号                       # 玩家（默认公共信令）
python mclink_core.py create 房间号 --sig udp --server 1.2.3.4:42339   # 自建信令
python mclink_core.py join   房间号 --sig manual --peer 房主公网IP:端口  # 手动IP
```

## 三种信令方式

| 方式 | 适用场景 | 说明 |
|---|---|---|
| **公共信令（默认）** | 普通玩家，什么都没有 | 经免费公共 MQTT 节点（broker-cn.emqx.io 等）交换公网地址和兜底中继，无需注册、无需服务器 |
| 自建信令 | 你有云服务器，想要更好中继速度 | `python mclink_server.py --port 42339`，放行该 **UDP** 端口，客户端信令方式选「自建服务器」 |
| 手动 IP | 公共信令被墙/懒得开软件 | 工具会显示你的公网地址（STUN 探测），双方用微信互发后同时点开始 |

## 第三方联机方案（需自行注册，本工具未内置）

| 方案 | 特点 | 门槛 |
|---|---|---|
| [Tailscale](https://tailscale.com) | 组虚拟局域网，稳定好用 | 双方注册账号装客户端 |
| [ZeroTier](https://zerotier.com) | 同上，老牌 | 双方注册账号 |
| [playit.gg](https://playit.gg) | 免费隧道，房主单人装即可 | 房主注册账号 |
| 樱花内网穿透 / frp | 免费隧道节点 | 需注册/自建 frp 服务端 |

这些都是成熟方案，注册登录后按官网指引即可，和本工具不冲突。

## 工作原理

```
玩家 MC 客户端 ──► 127.0.0.1:25565（本地监听）
                        │  隧道（UDP 打洞直连，失败则中继兜底）
                        ▼
              房主端 ──► 127.0.0.1:游戏端口（MC 局域网世界）
信令（MQTT/UDP）：只交换公网地址 + 中继兜底；打洞成功后游戏数据点对点直达
```

- 启动时经 STUN（小米/腾讯公共服务器）探测本机 IPv4 公网映射，仅探测不发数据
- 隧道帧格式：`魔数"MC" + 类型(1B) + 流ID(2B) + 载荷`，类型：打洞/开流/数据/关流
- 打洞超时自动切换中继；公共信令模式下大包自动分片

## 已知限制

- 对称型 NAT（手机流量常见）打洞成功率低 → 自动走中继兜底
- 公共信令中继经免费共享节点转发，带宽/稳定性尽力而为；追求流畅建议自建信令或有线宽带打洞
- 房主必须先「对局域网开放」才能被接入；端口每次开放都可能变
- 防火墙首次运行会弹窗，选择「允许访问」即可
- 自动化测试覆盖 1 房主 + 1 玩家全链路（本地信令直连、公共信令直连、公共信令中继）；多人房间逻辑已实现但未做自动化验证，正式使用前建议先两人实测

## 自测

```bash
python test_mclink.py          # 全部（子进程隔离跑三组）
python test_mclink.py udp         # 仅自建信令模式
python test_mclink.py mqtt-direct # 仅公共信令直连（连真实公共节点）
python test_mclink.py mqtt-relay  # 仅公共信令中继兜底
```

每组测试在本机完整跑一遍：信令 + 房主端 + 玩家端 + 模拟游戏端口，验证 TCP/UDP 双向转发和并发连接。
